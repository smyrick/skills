# Visuals and dense slides

## Choose the source by what the audience needs to see

- **Illustration, texture, or a cutout.** Use image generation when an original raster asset helps establish the setting, distinguish actors, or make a sparse chapter break memorable. Reuse supplied or approved art when it already does that job.
- **Product behavior.** Capture the real interface or record the brief action that proves the point. Crop to the evidence and add editable callouts. If a mockup better serves a fictional example, label it as illustrative and build any exact text and states as editable elements.
- **Values, labels, and relationships.** Use an editable chart, table, text, or diagram. Use native slide shapes or the deck’s existing graphics code for paths, status changes, and handoffs. Reuse approved marks for recognizable tools.

## Generate an asset for its slot

Describe the asset’s job, the crop and placement, and any empty area needed for slide text. Supply a style reference or palette if the deck already has one. Identify which inputs are references and which image is being edited. For cutouts that will move separately, request transparent backgrounds, keep the alpha channel, and inspect the edges on the actual slide background. Keep titles, labels, and data in the deck. For a set, keep viewpoint, scale, and lighting consistent while giving each subject a silhouette the audience can distinguish at its displayed size.

Inspect the result in the slide and revise one mismatch at a time. Save the selected asset alongside the deck and reference that copy. If generation is unavailable, use a suitable supplied asset or carry the slide with typography and existing shapes.

## Give dense evidence a quiet frame

Lead with the finding or decision. Group values by the comparison the room needs to make. Keep units, baselines, and scope attached to those values. Show the few rows or states needed to follow the argument and put the full report in an optional view or appendix. Leave the frame still when people need to compare several values at once. When a cue makes the reasoning easier to follow, reserve space for it and highlight one row or add one result while the rest stays in place. Keep status readable without color.

**Example.** Open a release chapter with one illustration and the title **Can we ship the change?** On the next slide, hold a compact verification matrix in place. Bring the failing compatibility row into focus as the presenter asks what would stop the release. Keep the two client versions and the failing check legible in the final still. Put the full test log behind an optional inspection. See [interactive decks](interactive-decks.md) for choosing and rehearsing the reveal.
