# Interactive decks

## Plan the reveal

For a slide with motion, specify the opening frame, what each press reveals, what stays in place, and what the presenter says. Add a press when the room should predict an answer, absorb evidence or see a new decision. Keep optional inspection, such as opening a full test report, within its current reveal. Use the normal deck controls for the rest of the sequence.

Use one example across the workflow. In a lifecycle diagram, keep stage names, order and colors consistent as you expand one stage or return to the overview. Across app screens, keep the work item identifiable and show the actual handoff, such as an issue constraint appearing in a PR or a failed check sending work back to its owner. Give each artifact its own identity. Reserve room for the next reveal so the surrounding frame stays steady.

When a phrase or figure becomes the focus, move the existing element when the format allows. Quiet surrounding context and omit a redundant heading. Restore the title when it introduces the specific example. Keep required evidence and labels readable. Place a measurement where it explains the example or sets up the next decision. Label actuals and forecasts where they appear. Keep comparisons aligned and reveal the next value when it answers the speaker’s next question.

**Example.** Start with a workflow overview and a few quiet ideas. Each press centers one idea. Lift “Shorten tool responses” from the background, then carry it into the title as a compact test result appears. Show the passing result and a failing case, with the full report available on request. Put the cost breakdown after the example if it leads into the next decision.

## Build for the delivery format

Use the deck’s native builds or transitions when they can carry the same object through the change. In a web deck, use the existing slide state and animate the elements whose meaning changes. Keep the title, adjacent cards, and controls steady. Separate optional inspection from the presenter’s next advance. Use adjacent slides with the same layout when builds are unavailable. Use a brief recording when the behavior of a real interface is the evidence, and give the room a still of the decisive moment.

## Rehearse the actual sequence

- Check the dense frames and adjacent reveals in presentation mode at the intended stage size. For a 16:9 talk, 1920×1080 and 1280×720 are useful checks. Check narrow width when mobile is part of the delivery. Trim copy or adjust the layout before shrinking the type the room needs to read.
- Walk forward and back using the controls the presenter will use. For a web deck, also try a direct reveal link, reload, and rapid advance or skip. If the presenter uses a clicker, separate notes window, or touch controls, check those paths and verify the notes follow the visible reveal.
- Make each settled frame work with reduced motion. Cancel interrupted transitions so stale elements do not appear on the next frame. Hide unrevealed text and controls from assistive technology until their cue. If the audience will receive a static export, include the settled frame or sequence that carries the evidence and conclusion. Open the exported file to verify those states made it through.

## Revise a hosted edition

Start with the named edition and the latest source. Locate comments by the exact slide and reveal, and preserve collaborators’ changes when merging. Keep drafts and archives available according to the deck’s versioning scheme. When publication is authorized, reopen the exact live edition and reveal after deploying. Check that the updated content, styles and controls load from a fresh visit. Use the site’s existing asset versioning if a cached entry serves an older revision.
